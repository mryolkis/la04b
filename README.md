# La 0.4b

Кодировщик и декодировщик lossless-аудио La 0.4b на Rust, CLI `la-rs` и
компонент воспроизведения для foobar2000. Rust-библиотека работает самостоятельно,
без оригинальной `la-core.dll` и сторонних Cargo-зависимостей.

Поддерживаются LA04 и WAV PCM 16 бит, один или два канала, режимы normal/high,
файлы с таблицей поиска и без неё. Кодирование сравнивается побитно с эталонами
оригинального кодека. При декодировании сохраняются заголовок и хвост WAV,
проверяется CRC аудиоданных.

## Сборка

Нужен [rustup](https://rustup.rs/). Версия **Rust 1.100.0** закреплена в
`rust-toolchain.toml`; оба пакета используют **edition 2024** и MSRV **1.100**.

```sh
cargo build --release --locked
```

Исполняемый файл: `target/release/la-rs`, в Windows — `la-rs.exe`.
Сборка и установка компонента описаны в [foobar2000/README.md](foobar2000/README.md).

## GitHub Actions

Workflow [Build](.github/workflows/build.yml) запускается при push, pull request
и вручную через **Actions → Build → Run workflow**. Используется Rust из
`rust-toolchain.toml`; дополнительные secrets не нужны.

- Rust workspace (библиотека, CLI и FFI staticlib) собирается в release для
  Linux x64, macOS ARM64 и Windows x86/x64. На каждой платформе запускаются
  Rust-тесты; в Linux также проверяются форматирование и Clippy.
- В Windows отдельно собираются компонент foobar2000 и тестовые C++ компоненты
  для x86/x64. SDK загружается и проверяется существующим `foobar2000/build.ps1`.

Готовые файлы доступны в **Actions → Build → выбранный запуск → Artifacts**:

| Артефакт | Содержимое |
| --- | --- |
| `la-rs-<target>` | CLI для соответствующей ОС и архитектуры |
| `foo_input_la` | Общий установочный пакет `foo_input_la.fb2k-component` для x86/x64 |
| `foo_la_test` | Тестовые DLL для x86/x64 |

При скачивании CLI для Linux/macOS из ZIP-архива может потребоваться
`chmod +x la-rs`. Тестовые C++ компоненты в CI только компилируются: запуск
проверок внутри плеера требует установленного foobar2000. Три игнорируемых
Rust-теста с внешними дампами `local/reference` также не запускаются.

## Использование

```sh
cargo run --release -- input.wav output.la
cargo run --release -- -high input.wav output.la
cargo run --release -- -d input.la restored.wav
cargo run --release -- --help
```

| Параметр | Действие |
| --- | --- |
| `-high`, `--high` | Усиленное сжатие |
| `-noseek`, `--no-seek` | Кодирование без таблицы поиска |
| `-d`, `--decode` | Декодирование в WAV |
| `-overwrite`, `--overwrite` | Разрешить замену выходного файла |
| `-cin`, `--stdin` | Читать вход из stdin; также можно указать `-` вместо имени |
| `-outputraw`, `--output-raw` | Сохранить промежуточные стадии кодирования |
| `--` | Завершить обработку параметров |

Если выходное имя опущено, расширение входного файла заменяется на `.la` или
`.wav`. Выход кодировщика должен поддерживать позиционирование.

## Библиотека

`encode`, `encode_wave` и `decode` выполняют полное преобразование.
`Encoder` предоставляет покадровое кодирование, а `Decoder` — чтение кадров,
перемотку и отмену долгих операций. Формат WAV представлен типом `wave::Wave`.
Единицы измерения и поведение CRC описаны в [docs/codec.md](docs/codec.md).

## Проверки

Запускаются из корня проекта:

```sh
cargo fmt --all -- --check
cargo clippy --workspace --all-targets --locked -- -D warnings
cargo test --workspace --release --locked
```

В `tests/fixtures` хранятся пять небольших WAV и 20 эталонных LA-файлов:
mono/stereo, normal/high, с таблицей поиска и без неё. Тесты также проверяют
CRC, повреждённые данные, многопоточную обработку, перемотку и отмену.

Три дополнительные проверки внутренних стадий оригинальной DLL помечены
`ignore`: для них нужны внешние дампы в `local/reference`. Их подготовка
описана в [tools/README.md](tools/README.md).

## Структура

```text
src/                  библиотека, CLI и внутренние тесты
tests/                тесты воспроизведения и эталонные аудиофайлы
foobar2000/           C++ адаптер, Rust FFI и сборка компонента
tools/                генерация эталонов, проверки и замеры
docs/                 сведения о кодеке
local/                локальные записи, внешние инструменты и старые отчёты
target/               результаты Cargo и временные данные проверок
```

`local/`, `target/`, SDK, сборки и установочные пакеты foobar2000 исключены
через `.gitignore`. Для обычной сборки и Rust-тестов содержимое `local/`
не требуется.

Проект восстанавливает поведение La 0.4b, разработанного Michael Bevin
в 2002–2004 годах. Исходный кодек и его DLL нужны только для дополнительных
проверок совместимости и не входят в Rust-сборку.
